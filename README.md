# GitHubProject_for_MAGD150
This repository is for the GitHub Project submission for MAGD 150.

This repository contains all three versions of my Etch-A-Sketch program that I've submitted as lab assignments 4, 5, and 9 respectively.

## Version 1: Etch-A-Sketch 1.0 (Lab Assignment 4)
This assignment originally intended for creating a project focused on If/Else and For-Loop statements, as well as interaction with mouse clicks and keyboard presses. Through all this, another requirement was to have "movement" in the sketch. I ended up coming up with the idea I submitted to this assignment on complete accident. I focused on the "movement" aspect first, and I remembered seeing an example program in the p5.js documentation of a simple circle moving across the screen from left to right. I tried copying it, and made a revelation when I put the "background" statement in the "setup" function instead of the "draw" function. When the circle moved, the places it was previously in stayed on the screen. Because it only moved one pixel per frame at max, it looked like it just left a black trail wherever it went. I initially thought this would be a problem - this isn't what I had intended for the program to do. But then the idea of thinking about it like a cursor that could draw on the screen began to form in my mind, and my perspective shifted. It wouldn't be a bug - it would be a feature!

From there the idea of thinking about it like an Etch-A-Sketch formed, providing a gameplan for the rest of the program. I decided to make a program that would basically do what an Etch-A-Sketch could, with a few extra additions. The If/Else statements fell into place alongside the keyboard interaction. I mapped moving the cursor to WASD, and threw in some extra functions - 'e' sets the cursor to "draw" mode, 'x' sets it to "erase" move, 'r' resets the position of the cursor, and 'c' clears the entire screen from everything that was drawn. Additionally, clicking the mouse changed the size of the cursor. The last stickler was implementing a For-Loop, so I decided to map one more key, 'q'. Pressing 'q' automatically creates a "diamond" shape to the immediate right of the cursor's position, and it's implemented using a for loop.

## Version 2: Etch-A-Sketch 2.0 (Lab Assignment 5)
This assignment was an extension of the previous assignment - creating "buttons" that responded to mouse or keyboard input only when the mouse cursor is hovering over them. So, naturally, I made this project an extension of the previous project. It was as simple as expanding the screen a little and adding a "HUD" where the buttons could be. There are a few differences from this version to the previous version, aside from this. Movement is still mapped to WASD - that remained exactly the same. But mostly everything else about how the program is interacted with was changed. The "create diamond" function was scrapped entirely, and I also removed the "reset cursor" function, as I added some additional If/Else statements to ensure the drawing cursor couldn't leave the boundaries of the screen. "Draw", "Erase", and "Clear" became clickable buttons. However "Clear" still requires pressing the 'c' key. Changing the size of the cursor also became a set of buttons to manually change the size of the cursor on the fly.

## Version 3: Etch-A-Sketch 3.0 (Lab Assignment 9)
This assignment was to choose a "library" for p5.js to work with, then create a project with it. I used the p5.Modbuttons library by incorporating the functionality of buttons, sliders, and dials into the Etch-A-Sketch 2.0 program. The program still has the analog WASD controls for the cursor, but they are no longer required for moving the cursor.

The library allows for the implementation of buttons, sliders, and dials. Buttons are exactly what they sound like, they can be implemented to function in a way similar to the primative iteration of the buttons showcased in week 5's lab lecture. Sliders allow for you to click and drag a knob along a horizontal or vertical track, and be programmed with functionality to have different things occur when the slider is at certain positions. Dials are circles that can be rotated by clicking and dragging them in a clockwise or counterclockwise direction. Just like sliders, they can be programmed to make things occur when the dial is spun forwards or backwards.

I used each of the three interactable tools that the p5.Modbuttons library allowed me to implement differently. I replaced the simple implementation of the "draw", "erase", and "clear all" buttons with actual buttons implemented using the library. This came at the cost of not being able to label them (because for some reason I could never get text to layer on top of them) but they work the same as before. I replaced the size changing buttons with a slider that changes the size of the cursor based on the slider's position. And I also added dials that can be used to control the cursor's x and y positional variables, like a real Etch-A-Sketch.
